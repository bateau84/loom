# skill-authoring Reviewer Assessment

Reviewer-only domain contract. It does not create Loom authority, product meaning, or proof.

## Review criteria

- **Discovery contract:** the description names the capability, uses concrete retrieval anchors for intended work, and defines sibling negative space where overlap exists without becoming a miniature workflow.
- **Trigger resilience:** edits do not casually drop known useful lexical/symptom/tool anchors; any meaningful description compression is treated as a re-test signal rather than assumed harmless.
- **Practitioner completeness:** `SKILL.md` contains the minimum load-bearing method and no Reviewer/Critic rubric leakage.
- **Progressive disclosure:** the normal path is usable from `SKILL.md`; references contain depth rather than missing core behavior and do not form deep answer chains.
- **Shape fitness:** the body structure fits the skill type and domain instead of mechanically applying one template to technique, reference, pattern, and discipline skills.
- **Risk-matched specificity:** instruction precision matches consequence and fragility; low-risk expert work is not over-scripted, while destructive/security/protocol work is not left dangerously vague.
- **Durable knowledge boundary:** reusable procedure and heuristics live in the skill; volatile operational facts are sourced from an appropriate current authority or explicitly freshness-governed.
- **Composability:** the skill is useful independently without becoming a monolith or duplicating responsibility better owned by siblings.
- **Grounded behavior change:** new or tightened discipline rules have an observed failure, user counterexample, review finding, incident, or equivalent RED rationale rather than invented justification.
- **Authority/side-effect discipline:** methodology does not silently grant product, filesystem, credential, execution, or user-decision authority.
- **ASSESSMENT.md**, when present, is domain-specific Reviewer methodology rather than generic correctness prose.
- **QA.md**, when present, contains residual-confidence attacks distinct from normal review.
- **Evaluation discrimination:** traps and negative expectations fail when defining behavior is ignored; phrase presence and model self-report alone are not behavioral proof.
- **Source integrity:** consequential version/API/tool claims and imported methodology retain enough provenance to verify or refresh them; obsolete AOS workflow mechanics are not revived as portable rules.

## Review depth

Scale review depth with consequence, uncertainty, invocation frequency, sibling-trigger overlap, knowledge volatility, reference fan-out, number of consuming agents, and blast radius.
