# skill-authoring Quality Assurance

Critic-only adversarial contract. Assume competent production and Reviewer conformance have already occurred; attack residual false confidence without creating new authority.

## QA criteria

- Attack **retrieval brittleness**: can the skill look well-authored yet fail to load for realistic paraphrases, symptoms, filenames, or tool-oriented requests because its description only matches author vocabulary?
- Attack **trigger capture and sibling conflict**: can a broad description or duplicated capability make this methodology dominate neighboring work despite apparently clean prose?
- Attack **monolith failure**: has one skill accumulated several independently useful responsibilities whose interaction increases context cost, contradictory guidance, or change blast radius?
- Attack **progressive-disclosure inversion**: is a load-bearing rule hidden in an optional reference, or has duplicated reference material bloated the default context enough to defeat retrieval/usefulness?
- Attack **stale expertise amplification**: can a fast-changing operational fact, API behavior, endpoint, owner, deployment assumption, or version claim become confidently wrong across many future dispatches?
- Attack **over/under-specification**: can exact procedure unnecessarily suppress expert judgment in low-risk work, or can vague advice leave a destructive/security/protocol boundary unenforced?
- Attack **ungrounded rule accretion**: did a behavioral rule enter the skill without an observed failure or evidence, making folklore permanent and difficult to falsify?
- Attack **authority laundering**: can reusable guidance quietly create semantics, permissions, destructive actions, credentials, or user decisions?
- Attack **self-confirming evaluation**: can the candidate, its wording, or a synthetic scenario make the eval pass without exercising the real decision boundary or observable output?
- Attack **source/provenance erosion**: did migration or compression preserve the sentence while losing why it exists, what evidence supported it, or which obsolete mechanics were intentionally rejected?
- Test whether ASSESSMENT and QA are genuinely independent or merely duplicated checklists with different severity words.

## QA depth

Increase QA depth where a shared wrong assumption could survive competent production and normal review, especially for ubiquitous, high-authority, security-sensitive, or frequently evolved skills.
