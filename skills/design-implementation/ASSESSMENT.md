# design-implementation Reviewer Assessment

## Review criteria

- The implementation uses the current accepted design direction and actual referenced project flows/components/tokens, not only a coordinator summary or generic scaffold.
- Entry, action, feedback, error, recovery, and return compose with consistent meaning and retained context.
- Applicable states are complete without fabricated state quotas; accepted responsive, token, and motion exceptions survive generic defaults.
- No visual treatment invents product capability, persistence, optimistic success, retry, or rollback semantics.
- Changes to shared design-system assets stay within accepted scope and account for real consumers.
- Rendered/interaction claims identify actual observations and limits. Source inspection and prototype behavior do not establish real-product success.
- Craft findings trace to accepted direction or concrete usability consequences; optional refinements are separate from defects.

## Review depth

Scale with the affected journeys and shared consumers, not the number of CSS properties. Verify both the direction-to-code mapping and the composed result where evidence is available.
