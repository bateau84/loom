# github-action Quality Assurance

Critic-only adversarial contract. Assume competent production and normal review have already occurred; attack residual false confidence without creating new authority.

## QA criteria

Assume the action is invoked by a privileged workflow against a repository controlled as far as the caller permits. Attack every layer between `action.yml` and the released executable bytes.

- **Input-to-code attacks:** inject shell metacharacters, newlines, quoting edge cases, Unicode/encoding tricks, option-like values, glob characters, template syntax, and multiline payloads into every input/context field. Try to reach shell, PowerShell, JavaScript eval/template, regex, query, path, or workflow-command interpretation.
- **Workspace-as-hostile-filesystem:** create symlinks/hardlinks, nested traversal paths, filenames beginning with `-`, FIFOs/sockets, huge trees, malicious archives, executable lookalikes, poisoned config files, and cwd/PATH shadow binaries. Test read/write/delete/archive/publish operations against them.
- **Argument/option confusion:** turn a supposedly safe argument into a CLI flag, response file, config path, plugin/module path, repository/ref selector, output path, or remote URL that changes the invoked tool's authority.
- **JavaScript bundle substitution:** compare reviewed source/lockfile with committed `dist`; try stale or malicious generated bytes, hidden vendored dependencies, source-map leakage, dependency confusion, lifecycle/build-script compromise, and tests that exercise source while consumers execute different code.
- **Process-spawn escape:** find any path where an argument array becomes `shell: true`, `exec`, `sh -c`, PowerShell expression text, or an attacker-selected executable through PATH/cwd/env.
- **Composite-action injection:** attack direct expression interpolation into `run`, nested mutable `uses:`, shell differences, inherited env/PATH, output parsing, and local script lookup. Assume the caller grants more permission than the action author expected.
- **Container escape of assumptions:** attack mutable base/registry tags including `docker://...` images, poisoned build dependencies, the platform-required root execution model, writable mounted workspace, Docker socket/host mounts if present, metadata-overridden or shell-wrapped `ENTRYPOINT`, attacker-controlled args/env, image-layer secrets, and network exfiltration. Reject a Dockerfile `USER` assumption as unsupported for GitHub Docker actions rather than treating non-root as available containment evidence.
- **Container lifecycle state attack:** treat `pre-entrypoint`, main `entrypoint`, and `post-entrypoint` as separate containers. Poison or replace state carried through the workspace, `HOME`, or `STATE_*`; force main failure/cancellation; and test whether post/setup logic trusts stale or attacker-modified shared state.
- **Downloaded-tool substitution:** redirect URLs via inputs, redirects, mirrors, DNS/config, platform selectors, release metadata, or fallback paths; supply malicious archives; exploit missing checksum/signature binding; test partial downloads and TOCTOU between verification and execution.
- **Credential exfiltration:** extract tokens via child-process env, argv, git/npm/docker config, HTTP redirects/headers, debug output, exception text, summaries, `GITHUB_OUTPUT`/`GITHUB_STATE`, artifacts, caches, temporary files, or later `post` execution.
- **Output-to-privilege chain:** make outputs contain shell fragments, paths, refs, URLs, JSON/YAML fragments, matrix values, environment names, or package targets that a normal consumer could unsafely trust in a later privileged step.
- **Pre/post asymmetry:** force main-step failure/cancellation and see whether `post` runs with stale state, broader credentials, attacker-written state files, or unsafe cleanup paths. Attack `pre` before expected validation has happened.
- **Release/source split:** compromise the path from source to published action commit/tag/image: generated bundle replacement, tag movement, release-branch bypass, untrusted PR artifacts promoted into release, mutable container tags, or publishing from a dirty/unverified workspace.
- **Consumer-trust mismatch:** invoke the action from fork PRs, privileged release workflows, self-hosted runners, and reusable workflows. Look for an assumption that is safe only in the author's example workflow but unsafe for realistic consumers.
- **Persistence:** on self-hosted runners, check whether the action leaves credentials, processes, containers, modified global config, PATH/tool state, or files that affect later jobs.
- **Resource abuse:** use very large/malformed inputs, recursive repos, decompression bombs, unbounded matrices/file walks, or retry/network loops to turn the action into runner exhaustion or denial of service.

A demonstrated route to arbitrary code execution beyond the documented intent, secret disclosure, repository/cloud privilege misuse, release substitution, unsafe filesystem escape, or persistent runner compromise is blocking.

## QA depth

Be especially aggressive when an action is reusable across repositories because one shared wrong assumption can propagate widely.

Prioritize actions that:

- execute or download code;
- accept paths/URLs/commands/refs;
- use secrets or write-capable APIs;
- publish/sign/deploy;
- run on self-hosted runners;
- ship containers, generated bundles, or native binaries;
- are likely to be consumed from privileged workflows.

QA should try to break the trust model, not merely restate lint/style defects from normal review.
