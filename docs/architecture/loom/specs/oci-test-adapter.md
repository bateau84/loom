## Immutable finite input manifest

Manifest is a committed reviewed descriptor, not a caller-supplied arbitrary path list. Exact fields: `imageId: string` (exact below), `inputs: string[]` (finite sorted project-relative regular-file roots/files), `dependencyRoots: string[]` (finite installed dependency roots needed offline), `suites: Record<selection, Array<{id: string, argv: string[], requiredCaseIds: string[]}>>`, `requiredCases: Array<{id: string, file: string, name: string, criteria: string[]}>`, and `limits: {stageTimeoutSeconds: number, totalTimeoutSeconds: number, maxLogBytes: number, maxReceiptBytes: number}`. Reject unknown fields, duplicate IDs/inputs, nonpositive/noninteger limits and suite/case references without a selected source. Case IDs are stable manifest keys; names/files identify actual reported test cases, and criteria trace to accepted Brainstorm Verification 1–4 or adapter controls, not new requirements. Implementation review must resolve concrete lists/ceilings before admission; no wildcard 'entire checkout' or default host environment. Allowed roots are limited to required `plugins/loom`, `scripts`, `dashboard`, associated package/lock/TypeScript inputs and needed installed dependencies; include any additional fixture/document/config-independent test input only as an explicit reviewed manifest revision. Exclude actual OpenCode/app config, `.env`, credentials, sockets/devices, VCS internals, `.loom`, session/report/state stores, runtime-root selectors and databases. Fixtures representing secrets/state are synthetic test inputs only and must be individually identifiable, not ambient installation files.

Revision 2 adds required `hostLaunch: {executables: Record<name, {path: string, sha256: string}>, safePath: string[], tempBase: string, scriptShell: string}` to that exact manifest schema. Pin Bash/env/Python/npm/Node/engine identities. This is finite reviewed readiness data, not a caller-selected executable registry or production config input. The earliest Bash/env/Python/safe-PATH values are literal pinned bootstrap source so no ambient interpreter need parse the manifest. Bootstrap/prelaunch source and executable mode are part of the reviewed source identity and post-run recheck; changes invalidate assessment/admission just as orchestrator changes do.

Enumerate selected roots deterministically with no link traversal; reject symlinks (including internal dependency links until deliberately represented as copied regular inputs), escaping paths, special files and changing entries. Do not dereference an outside dependency or silently omit needed files. Copy admitted regular files into a fresh private 0700 staging tree, mode-preserving only where needed (no setuid/setgid bits), then hash that **copy**. Recheck corresponding original bytes/paths after copying and after execution; concurrent change fails source relevance. No Git metadata is copied or mounted. Git fixtures initialize only their disposable container-local repositories.

Canonical input identity: sorted tuples `[relativePath, normalizedMode, byteLength, sha256]`; UTF-8 compact JSON array, SHA-256 of those bytes. `normalizedMode` is `executable` or `regular`; directory identity follows its contained files, empty required directories are listed separately. Receipt records manifest/adapter/driver/lockfile digests and this input digest. Container independently recomputes it before any tests. Git HEAD is supplementary provenance only; dirty/untracked selected bytes are not represented as HEAD proof. Every input expansion/change requires fresh safety assessment/admission against new digests, not a missing-file retry with a broader archive.

## Receipt and existing proof API

Emit one bounded final JSON test receipt on stdout after cleanup; retain bounded full stage output with digest references if needed. This is not signed authority or a runtime-evidence protocol. Required fields:

- `runId`, `selection`, `status` (`passed`/`failed`), `startedAt`, `finishedAt`;
- `source`: input digest, file tuple count, manifest/adapter/driver/lockfile digests, optional Git revision and source recheck result;
- `startup`: bootstrap/prelaunch source digests and executable identities, privileged Bash/startup-hook exclusion, clean pre-npm environment/config/cache/log root identities, actual npm dispatch and its status; no environment values containing secrets;
- `container`: actual ID, ownership nonce, exact image ID, verified network/mount/entrypoint configuration, toolchain identities;
- `stages`: ordered command argv, case/discovery identities, executed/passed/failed/skipped counts where applicable, exit code/signal/timeout, bounded output or output digest/path;
- `isolation`: actual guard/canary/child-root/listener control results and selected process-boundary coverage;
- `stageEnvironments`: explicit Python-discovery/test, Bun/plugin, static-check and other selected stage root identities, startup ordering and actual descendant propagation controls; inert driver bootstrap separately identified;
- `cleanup`: container and staging removal outcomes, unresolved owned resource IDs; `error` on failure.

Cleanup also covers the prelaunch-owned HOME/config/cache/log/temp roots. The outer bootstrap/prelaunch emits final success only after nested adapter success, complete receipt verification, source recheck and all owned cleanup, forwarding nonzero/signal/timeout even if some nested stage printed success. Actual recorded npm command is a dispatch record, not a synthetic new tool observation. All provenance remains under the actual outer executor event; no nesting transfers session/step identity or creates claims for peer events.

Missing/unknown required result, count inconsistency, output limit overflow without complete retained results, failed stage/cleanup or source mismatch makes `status=failed` and host exit nonzero. Hashes identify actual bytes; they do not confer authority. Do not include credentials/DB payloads. The adapter must surface host exit/error in the shell's actual result; merely printing `passed` never suffices.

Current outer shell event is owned by the actual executor role/session/step/attempt. Do not pass fake Step IDs into inner fixtures as origin proof or use peer observation IDs. The current executor uses its new shell observation IDs with existing `loom_evidence_claim`/`loom_verification(prove)`; references exact adapter/container execution and tested source/coverage. Existing command-pattern acceptance of the named test entrypoint supplies mechanical test classification only; Reviewer still checks substantive receipt/output and source relevance. No edits to proof records, evidence regexes, role permissions or observation framework are required. If the current host result cannot supply successful completion/error and sufficient provenance, report a capability gap; do not manufacture a satisfying observation. Historical Diagnostic results stay attributed to their original OQ/session and old source.
