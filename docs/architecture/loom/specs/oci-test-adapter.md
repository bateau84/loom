## Components and exact entrypoint

Worker implements:

1. `package.json` script `test:loom-sandbox`: exactly `python3 -I -B scripts/loom-oci-test-adapter.py` with no command chain; no corresponding pre/post script. Python isolated startup excludes user site/PYTHONPATH imports, and `-B` suppresses bytecode writes. Existing package `test` and canonical runner remain unchanged.
2. Stdlib-only host orchestrator `scripts/loom-oci-test-adapter.py`; imports only stdlib, never Loom/Bun/plugin/application configuration or the in-container driver on host. It only validates arguments, snapshots/hashes approved inputs, invokes finite OCI lifecycle operations, captures output and cleans owned resources.
3. Stdlib-only in-container driver `scripts/loom-oci-test-driver.py`, and a reviewed source manifest `scripts/loom-oci-test-manifest.json`. All test imports/processes execute inside the container.
4. Adapter pure command/manifest/receipt tests with explicit external engine doubles; these do not claim real isolation or feature integration. Their source is reviewed before execution; execute them in the admitted container, not as a host plugin bootstrap.

Public invocation: `npm run test:loom-sandbox -- --suite <selection>`; selections are exactly `isolation`, `native`, `canonical`, `static`, `all`. No arbitrary command, path, image, engine flags, mounts, environment overrides, inference or shell-eval input. Unknown/duplicate options fail. `all` is the ordered union, not a shortcut. Every selection first verifies toolchain/input/container identity and runs the isolation controls; `native` also runs the corrected cleanup fixture before the native cases. `all` order: isolation → corrected cleanup → native → canonical → static. Use argv arrays, no `shell=True`, in orchestrator/driver subprocesses; the single literal package script necessarily uses npm's ordinary script launcher, separately reviewed below.

Host npm/Node/Python and OCI engine must already exist and their executable identities must be inspected before admission. No package installation or npx/bunx resolution. Review npm's literal script shell, absence of hooks, local `.npmrc`/parent/global configuration influence, NODE_OPTIONS/preload, PATH selection, npm cache/log writes and env inheritance without opening credentials. Do not execute a configured host preload or let npm run against production HOME/config. The admitted launch uses a fresh owned environment/config/cache/log boundary **before npm starts**, and no credentials/services enter that environment. Current `shell.ts:83–104` supports selected XDG/Python prefixes but not HOME, NODE_OPTIONS or a general `env -i`; this document does not assert that a clean npm launch can be self-elevated. General must positively establish an existing authorized clean process launch with the literal package command before admission, or route that exact capability gap for normal structural reconsideration. A shell-prefix trick, an added launch wrapper, permission mutation or relabelled adapter run is not a solution. ## Immutable finite input manifest

Manifest is a committed reviewed descriptor, not a caller-supplied arbitrary path list. Exact fields: `imageId: string` (exact below), `inputs: string[]` (finite sorted project-relative regular-file roots/files), `dependencyRoots: string[]` (finite installed dependency roots needed offline), `suites: Record<selection, Array<{id: string, argv: string[], requiredCaseIds: string[]}>>`, `requiredCases: Array<{id: string, file: string, name: string, criteria: string[]}>`, and `limits: {stageTimeoutSeconds: number, totalTimeoutSeconds: number, maxLogBytes: number, maxReceiptBytes: number}`. Reject unknown fields, duplicate IDs/inputs, nonpositive/noninteger limits and suite/case references without a selected source. Case IDs are stable manifest keys; names/files identify actual reported test cases, and criteria trace to accepted Brainstorm Verification 1–4 or adapter controls, not new requirements. Implementation review must resolve concrete lists/ceilings before admission; no wildcard 'entire checkout' or default host environment. Allowed roots are limited to required `plugins/loom`, `scripts`, `dashboard`, associated package/lock/TypeScript inputs and needed installed dependencies; include any additional fixture/document/config-independent test input only as an explicit reviewed manifest revision. Exclude actual OpenCode/app config, `.env`, credentials, sockets/devices, VCS internals, `.loom`, session/report/state stores, runtime-root selectors and databases. Fixtures representing secrets/state are synthetic test inputs only and must be individually identifiable, not ambient installation files.

Enumerate selected roots deterministically with no link traversal; reject symlinks (including internal dependency links until deliberately represented as copied regular inputs), escaping paths, special files and changing entries. Do not dereference an outside dependency or silently omit needed files. Copy admitted regular files into a fresh private 0700 staging tree, mode-preserving only where needed (no setuid/setgid bits), then hash that **copy**. Recheck corresponding original bytes/paths after copying and after execution; concurrent change fails source relevance. No Git metadata is copied or mounted. Git fixtures initialize only their disposable container-local repositories.

Canonical input identity: sorted tuples `[relativePath, normalizedMode, byteLength, sha256]`; UTF-8 compact JSON array, SHA-256 of those bytes. `normalizedMode` is `executable` or `regular`; directory identity follows its contained files, empty required directories are listed separately. Receipt records manifest/adapter/driver/lockfile digests and this input digest. Container independently recomputes it before any tests. Git HEAD is supplementary provenance only; dirty/untracked selected bytes are not represented as HEAD proof. Every input expansion/change requires fresh safety assessment/admission against new digests, not a missing-file retry with a broader archive.

## OCI lifecycle and isolation

Use exact already-approved local image ID `6f4f933b7e6327a090c49b968a75c31a9a717415f81b207dcfda3329d5e40da4`, no tag fallback/pull/build. Diagnostic verified Bun 1.4.2 (binary SHA-256 `a83d263767d839e4d2649ca8e35d07159c7afc99afdc96d731ced29e056dda0c`), Python 3.12.14, Git 2.39.5 and flock in that image; fresh driver verification remains required. Static check interpreter availability must be proved too; no fetching Node/TypeScript or silently substituting a different checker/toolchain.

Container create uses network none, no host binds/volumes, host namespaces, privileged flags, devices or engine socket. Explicit test-driver entrypoint overrides the inherited service entrypoint; do not start OpenCode/services. Copy staging tree into the stopped container's private `/workspace`, with no archive traversal/external links, then start fixed driver. Inspect actual configuration before starting; compare image, network, mounts, entrypoint and explicit environment against expected values. Neither host engine nor original source/Git/state is mounted. Driver's mutable test tree is an internal disposable copy; no test writes return to the product checkout. Set resource/time limits suited to the measured bounded suite, and record them; no unlimited retry.

Only exact recorded engine operations are allowed in adapter code: inspect image, create owned uniquely named container, copy staged inputs, inspect container, start/attach, wait/log, remove **that** container. Use actual returned container ID plus ownership label/run nonce, not a broad name selector or prune. Construct minimal engine environment explicitly using reviewed engine runtime plumbing, not ambient credential/remote-endpoint variables. A rootless engine's runtime directory may be required for orchestration, but is never a test mount/input and does not authorize reading Loom databases. An unexpected engine/remote endpoint, required host data mount or unidentified ownership effect is a blocker.

Inside driver, create fresh empty roots and call copied `isolated_test_environment` before every Bun/plugin process. Preserve HOME/USERPROFILE/all XDG/TMP and `LOOM_TEST_ISOLATION_ROOT` inside container-private paths; strip ambient LOOM toggles and sandbox Git selectors in child env. Existing fixture guards suppress default dashboard autostart and reject raw unsafe launches. Positive listener controls may open/close a container-local ephemeral listener for detector validation; this is not permission to start host services. Synthetic canaries and real SQLite migration/child-root tests remain real execution, not mocked schema changes. External provider/host boundary and synthetic ExecRunner fixture can be mocked as accepted; mandatory registered-plugin behavior cannot.

Container logs/case results must prove exact native coverage and canonical test discovery, not merely a Bun zero exit. Driver rejects no-tests/empty discovery, filtered-away required cases, skipped mandatory cases and incomplete/truncated results. Include known canonical Python unit discovery and copied `run-unit-tests.py` selection, offline dependencies and actual static checks; missing `runner` or other setup is disclosed failure, not a skip/PASS. No inference-bearing eval selection or historical rescore. Logs may be retained as bounded owned execution artifacts but are excluded from source inputs.

Lifecycle: validate → snapshot → create/copy/inspect → execute/collect → inspect source relevance → cleanup → final result. Any failure/time limit/signal triggers owned cleanup. Exit 0 only if all selected stages succeeded, required results are complete, post-run source identity matches and cleanup removed owned container/staging. Cleanup failure is nonzero with resource identity retained for bounded recovery; it never counts as test success. No auto retry, fallback to host tests, engine installation, broad removal or history mutation. If cancellation/reopen arrives during an admitted process, current Loom fences prevent new operations/proof; preserve uncertainty until this process finishes/cleans up. The adapter cannot independently poll live Loom state or pretend cancellation killed an already-running host child.

## Receipt and existing proof API

Emit one bounded final JSON test receipt on stdout after cleanup; retain bounded full stage output with digest references if needed. This is not signed authority or a runtime-evidence protocol. Required fields:

- `runId`, `selection`, `status` (`passed`/`failed`), `startedAt`, `finishedAt`;
- `source`: input digest, file tuple count, manifest/adapter/driver/lockfile digests, optional Git revision and source recheck result;
- `container`: actual ID, ownership nonce, exact image ID, verified network/mount/entrypoint configuration, toolchain identities;
- `stages`: ordered command argv, case/discovery identities, executed/passed/failed/skipped counts where applicable, exit code/signal/timeout, bounded output or output digest/path;
- `isolation`: actual guard/canary/child-root/listener control results and selected process-boundary coverage;
- `cleanup`: container and staging removal outcomes, unresolved owned resource IDs; `error` on failure.

Missing/unknown required result, count inconsistency, output limit overflow without complete retained results, failed stage/cleanup or source mismatch makes `status=failed` and host exit nonzero. Hashes identify actual bytes; they do not confer authority. Do not include credentials/DB payloads. The adapter must surface host exit/error in the shell's actual result; merely printing `passed` never suffices.

Current outer shell event is owned by the actual executor role/session/step/attempt. Do not pass fake Step IDs into inner fixtures as origin proof or use peer observation IDs. The current executor uses its new shell observation IDs with existing `loom_evidence_claim`/`loom_verification(prove)`; references exact adapter/container execution and tested source/coverage. Existing command-pattern acceptance of the named test entrypoint supplies mechanical test classification only; Reviewer still checks substantive receipt/output and source relevance. No edits to proof records, evidence regexes, role permissions or observation framework are required. If the current host result cannot supply successful completion/error and sufficient provenance, report a capability gap; do not manufacture a satisfying observation. Historical Diagnostic results stay attributed to their original OQ/session and old source.

General validates these against accepted scope and records the exact permitted protocol/limits (or routes a real external boundary). Both answered questions must be consumed by the current Worker before execution. Questions preserve professional attribution; no parallel continuation/dispatch is inferred from answer success. Runtime OQ reconciliation fences completion; **there is no new automatic per-command safety-verdict enforcement**.
