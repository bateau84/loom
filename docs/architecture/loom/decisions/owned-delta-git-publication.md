**Status:** proposed for the owned-delta task

## Derived from and problem

Accepted task `de5fb9ee-0231-44f0-b1ca-f39ed4e1de51`: a step may publish only its exact admitted changes in a shared file, leaving unrelated pre-existing changes unstaged; foreign dirt cannot prevent its completion. Overlap/conflict, stale baselines or attempts, changed foreign bytes, absent proof, and cross-session interference fail closed. Interactive partial staging and assigning the entire file to its latest editor are explicitly excluded. No work on the diagnosed Leash workflow/repository is authorized here.

Current `plugins/loom/index.ts` records a whole-worktree fingerprint after a successful mutation (555–589, 10181–10199), then requires whole-file worktree/index agreement for staging/commit (619–673, 931–1043), and treats any dirty path with an attempt fingerprint as outstanding owned work (1051–1109). `plugins/loom/shell.ts` permits scoped `git add` paths, not a content-aware publication operation (320–339, 743–755). Existing file-write/step-authority and index locks serialize cooperating Loom tool calls (index.ts 2541–2613, 9708–9894), but neither a path scope nor a final fingerprint identifies a delta. The architecture/control-plane document's statement equating admitted *bytes* with commit authority needs narrowing to admitted *delta*.

## Invariants

1. **Origin:** The only candidate owned delta is a before/after transition of an admitted, successful, exactly identified mutation tool call under the current project, workflow, step, attempt, attachment and effective write scope. Capture the preimage before tool execution while holding its path/step locks; capture and durably record the postimage before releasing those locks. The tool result alone, a scope elevation, a whole-file fingerprint, or a user-authorized recovery of current bytes is not delta proof. A fresh child on the *same attempt* may consume durable delta proof, never manufacture it.
2. **Frozen foreign contribution:** For each path, keep the exact pre-first-owned-edit foreign snapshot `F` and the exact Git index/HEAD baseline `H` it is compared against. The step's owned projection `P` is obtained by replaying only proven owned edits onto `H`; the observed aggregate worktree `A` must equal a deterministic disjoint composition of `F` and those edits. Reversing the owned edits from `A` must reproduce `F` byte-for-byte. Other sessions' previously admitted or unadmitted edits remain foreign to this attempt. Never infer origin from equality to a later worktree snapshot.
3. **No ambiguous composition:** The transformation `H -> F` (foreign) and `F -> A` (owned) must be unambiguously separable and commute to the *same* aggregate when applied in either order. Reject overlapping deleted/replaced spans, competing insertions at a boundary, ambiguous repeated-text anchors, mode/type collisions, rename ambiguity, or a formatter/rewrite that changes foreign bytes. Equality of the complete replayed bytes, not merely non-overlapping line numbers, is necessary. A whole-file edit with no foreign contribution can be admitted as an owned replacement; mixed binary/symlink/create/delete/type/mode changes are refused unless the absence of foreign contribution is proved. Conservative rejection is better than guessing intent.
4. **Exact publication:** The staged blob/mode for a shared path must be `P`, not `A`. `F` and any other pre-existing work remain unstaged. Commit includes *only* exact staged projection receipts for this authority; unrelated staged index entries (even on other paths) remain a conflict rather than being silently swept into a commit. The worktree is not rewritten or reset to stage. After the commit, the same aggregate `A` differs from the new HEAD by exactly the proven foreign residual; that residual is not owned dirt.
5. **Freshness:** At each mutation, staging, commit and completion boundary revalidate project epoch, live step attempt, authority/attachment as appropriate, path identity, baseline HEAD/index, staged entries, current worktree, foreign snapshot and durable receipt revision. Any unexplained byte change, stale baseline, competing publication, missing snapshot, legacy path-fingerprint-only ownership, incomplete tool-call provenance, or non-commuting merge is a denial, not a new ownership claim. Once an attempt reopens, old receipts are non-authoritative. No fingerprint-only legacy migration/recovery may upgrade to delta proof.

## Options and decision

**A. Controlled three-way projection into the shared index (selected).** Observe each mutation's two exact states under current locks, persist an attempt-scoped chain and foreign baseline, then compute and validate a disjoint replay against the frozen Git baseline. A narrow Loom-owned publisher inserts the projected blob/mode into the index under index + file + step locks and stores a staging receipt. Commit and completion validate that receipt and residual. This retains ordinary Git status and the existing repository/index architecture. It costs bounded snapshot storage and strict conflict checks; Git's external actors remain outside Loom's cooperative-lock trust boundary.

**B. Private per-step Git index and tree with compare-and-swap ref update.** The same delta proof and disjoint replay are still required. A temporary index could isolate staging from foreign staged entries, but publication must update HEAD safely and reconcile the real shared index without discarding foreign entries. That adds two index state machines, crash recovery, and ref/index coordination without reducing the fundamental attribution problem. Reserve for a separately accepted need to publish concurrently with foreign staged entries.

**C. `git add -p`, `git apply --cached` supplied by an agent, or whole-file `git add`:** none proves the tool-call delta; the former two delegate attribution to untrusted agent-selected hunks, and the latter stages foreign bytes. Not acceptable as the authority boundary.

## Components, flow and lifecycle

- **Mutation admission/recorder:** Before an admitted edit/write/patch/formatter tool runs, under project path + step-authority locks, snapshot each target's exact bytes/type/mode and its Git baseline/index identity. Check a preceding attempt receipt's aggregate against this preimage; if there is any unexpected change since the preceding admitted mutation, stop rather than absorb it into this attempt. On successful return, while locks are still held, snapshot all postimages, verify the unchanged foreign contribution and disjoint replay, and atomically append receipts for all changed paths. A multi-path call is all-or-nothing for provenance; a partial/error call with changed files remains unproven and blocks publication/completion rather than disappearing. A no-op call adds no owned delta. Capture of a before/after snapshot must not assume the tool input describes every actual mutation; unsupported paths/side effects fail closed.
- **Durable proof:** Project-scoped runtime state owns versioned exact snapshots (or content-addressed blobs with checked content hashes) of `H`, `F`, admitted pre/post states and the derived owned projection, keyed by workflow/step/attempt/path and monotonically advancing receipt revision. Persist the step binding and tool-call admission identity. Snapshot size is bounded; unsupported/unreadable/oversized file states cannot enter shared-file delta publication. Before-tool pending intents are durable; after crashes, a pending intent whose preimage still exactly equals the current path/index can be discarded as a no-op; otherwise do not recover ownership by comparing only final bytes. Expire superseded records only after the attempt's commit/completion and audit retention requirements are satisfied; retain enough for fresh-session replay and post-commit completion. Runtime correctness-schema migration fences older writers; old schema-1 fingerprint ownership remains historical, not newly committable delta proof.
- **Projection/staging:** Provide a controlled publication operation rather than broadening the shell `git add` grammar. Under the same path + step locks and the project Git-index lock, check live attempt and invariant 5, demand a clean target index relative to the frozen `H` (and no foreign staged entries anywhere for this commit), build `P` from durable receipts, write exactly that blob/mode to the index and verify its Git object ID and mode. Store a receipt binding the attempt, baseline commit/index identities, projection, aggregate/foreign hashes, and resulting index entry. Plain `git add -- path` for a mixed-owned path must not remain an alternative path to stage `A`. Unmixed owned-only paths may continue the existing bounded path flow only if equivalent proof checks hold.
- **Commit:** Hold the index and all staged path/step locks from revalidation through Git commit and receipt finalization. Keep hooks disabled as the existing bounded commit path requires. Deny unrelated staged entries and mismatch of any staged entry to its current projection receipt. Validate the expected HEAD/ref, index, aggregate, foreign baseline and live attempt immediately before commit. A concurrent HEAD advance, index edit, or foreign worktree edit is a denial; after a crash between Git success and receipt finalization, reconcile only when the exact commit/tree/parent and projection are independently provable from durable precommit intent and current Git state, otherwise stop. Do not attach a later session's commit to an earlier receipt merely because bytes match.
- **Completion:** Replace dirty-*path* ownership with outstanding owned-*delta* reconciliation. For each attempt path prove its published projection exists in the expected commit history and that current worktree/index plus committed projection reconstitute the unchanged recorded foreign snapshot; then foreign-only dirt is excluded. Deny an uncommitted owned delta, a pending/unknown mutation, unexpected worktree/index divergence, or a stale/missing commit receipt. An owned step editing several paths must reconcile all of them before completion. Publication of an owned delta does not authorize removal, staging, or attribution of foreign bytes.

Lock keys must be project-scoped and acquired in canonical order using the installation-shared OS lock root. Tool-call path locks cover the entire before -> tool -> after -> durable receipt interval; publisher/commit/completion must serialize with relevant step lifecycle transitions. A file lock only orders cooperating Loom processes; an external Git process can ignore it. Re-read HEAD/index/worktree under locks, compare exact versions before and after significant Git operations, and fail closed on observed interference. Absolute protection against an uninstrumented process that changes bytes during the tool call and restores them is impossible from before/after snapshots alone; do not claim that guarantee without process containment or an exclusive enforceable repository writer. In particular, ordinary Git does not provide a cross-process atomic transaction over HEAD, index and worktree; unexpected external races detected after a partially completed commit require explicit safe reconciliation, never blind retry or resetting foreign work.

## Verification obligations

- Real Git integration: start with tracked `H`, user/session X makes foreign `F` in a shared file, admitted Y edit yields aggregate `A`; publisher stages only `P`; commit contains Y only; worktree still contains X; `git diff` reflects X alone; Y completes without claiming X. Repeat after process restart/fresh child on same attempt.
- Reject edits touching X's span, same-boundary inserts/ambiguous anchors, changed foreign bytes before staging and before completion, stale HEAD/index, a staged foreign path, a foreign staged portion of the same path, altered staged projection, change after an admitted edit, reopened attempts, forged/missing/legacy fingerprints, partial/error tool mutation and crash between staging/commit/receipt. Verify no rejection rewrites X's worktree or silently stages it.
- Race real parallel Loom sessions/processes on the same file, step reopen against in-flight edit, and index lock/commit against other stages. Assert canonical lock ordering, no stale receipt publication, and no cross-project or cross-attempt adoption. Exercise multiple edits of the same path and multi-file mutations, no-op, deletion, modes, symlink/binary, repeated text, untracked paths and mixed clean/dirty paths.

## Consequences / limits

The publisher is a narrow internal capability, not permission for arbitrary `git add -p` or custom agent-supplied patch text. Byte provenance proves admitted tool effects within the cooperating Loom mutation boundary, not the agent's intellectual authorship of identical text or an uncontained external actor's simultaneous writes. Fail closed where those cannot be distinguished. Existing recovery that adopts a whole current fingerprint cannot rehabilitate this kind of shared-file ownership. No observable recovery or retry policy beyond the accepted fail-closed behavior is selected here.
