No decisive probe is executed in this phase. Their results gate dependent implementation/rollout, not reviewed planning; Planner must place them ahead of that dependent work. Proven infeasibility goes to appropriate authority before silently weakening guarantees. Discovery can conclude with a structurally coherent recommendation and explicit early proof paths, not a claim these premises hold.

## Minimal feasible independent test realization

Choose an external supervised **rootless Linux process namespace sandbox** for initial proof, rather than requiring the unfinished old OCI adapter. A small audited launcher (outside plugin imports) constructs fresh user/mount/PID/network namespaces, private synthetic HOME/XDG/runtime roots, and a minimal read-only toolchain/source tree. Only explicitly approved copied source/fixtures and synthetic writable workspace enter. No production config/state, credentials, host home, Git metadata, engine sockets or inherited arbitrary file descriptors are mounted/passed. Synthetic Git repositories are created inside. Network is disabled. Drop capabilities after namespace/mount setup, set no-new-privileges, forbid mount/setns/ptrace/privilege-changing escapes with enforced syscall policy. `/proc` describes contained PID namespace; no inherited host process handles. Descendants inherit containment. Redirecting environment is defense in depth, never the enforcement claim.

The independent supervisor establishes and inspects restrictions **before** starting Bun/OpenCode or any product setup/import. It launches only after verifying namespace identities, mount allowlist, UID/capability state, descriptor allowlist and applied policy. Missing unprivileged namespace/toolchain/policy capability gives supervisor refusal before product execution. OCI or an isolated VM may later be a reviewed alternative transport, but no implicit pulls, privileged fallback or dependency on old adapter completion is accepted. Availability on this host is unproven; namespace approach is a design choice, not a local sandbox attestation.

### Synthetic-only evidence protocol

An outer witness creates a synthetic protected installation/sentinel outside the admitted inner mount tree. No live installation is discovered, opened or hashed. The child receives adversarial synthetic paths: direct absolute path, symlink traversal from allowed workspace, misdirected HOME/XDG and descendant helper. Probe opening synthetic protected data before plugin import, during setup and in a subprocess; require actual denied access or absent mount plus independently observed applied restriction. Record denial event/errno and containment identity. Witness reads only its own synthetic sentinel afterwards. Sentinel unchanged without access-restriction evidence is insufficient; successful container/process startup is insufficient.

Record source/host/toolchain/launcher/policy digest, synthetic target identity, pre-execution attestation, descendant evidence and bounded output. Include a preflight-refusal variant proving no child/import/setup event happened. Product logs cannot alone attest their own containment. Prohibit live DB comparisons even read-only. Test runner failure does not remove containment; supervisor retains control and captures process termination/unknown state. Synthetic host protocol tests use actual plugin/native hooks in this same boundary, not an ambient installed OpenCode session. No fake credentials or mocks may hide mandatory host admission paths; synthetic local effect servers can make lost-response behavior repeatable while remaining within containment.

## Controlled installation boundary

Stable standalone manager is shipped/accessible separately from plugin, with bounded dependency path and human-readable recovery manifest. It owns a small checksummed installation activation envelope: installation identity, active generation locator, supported format, monotonically increasing fencing token and transition/lock identity. This is unique **physical activation authority**, not a duplicate workflow state. Use OS-level exclusive manager lock and atomic synced manifest replacement; do not trust a damaged plugin's schema flag as fence proof.

All canonical writes and potentially persistent effects pass through managed custody. Before upgrading an old unfenced build, terminate/isolate old writers and establish inability to reopen protected generation; checking DB schema or bumping token alone is insufficient. New plugin processes lack direct write access to canonical generation except managed writer channel. Already-issued external operations may outlive clients; contain local writers to their custody and preserve observations, while remote outcomes may remain unknown. The broker checks current token immediately before invocation; admitted-before-fence operations are accounted separately. This is a new required boundary, not a claim existing plugin protections already enforce it.

## Protected cut and upgrade protocol

1. Installation manager closes **all installation admissions** and fences canonical writers; per-workflow pause alone is insufficient. Serialize with admission/reservation and finish durable acknowledged commits. Capture cut sequence and every outstanding admitted operation. Prevent old physical processes from writing source/candidate generations; keep attributed later observation intake in a separate recovery spool while admissions remain closed.
2. Inventory protected closure: installation/project identities, accepted content/decisions, Plan revisions, lifecycle/leases/grants/resource consumption, attempts/original contexts/results, observation/claim payloads, questions/consumer treatments, reviews/acceptance, mutation/handoff/publication receipts, operation records and required recoverable artifacts. Include acknowledged uncommitted user contributions from managed custody, not only Git commits. If required workspace/artifact bytes cannot be frozen/copied/verified, protection is incomplete and upgrade cannot start.
3. Create consistent SQLite backup through its supported backup mechanism under fenced cut; never main-file-only copy while WAL may contain committed facts. Copy referenced immutable object closure and protected custody artifacts, compatible prior code/toolchain manifest, schema/identity and outstanding-operation inventory. Sync data and manifest. Independent read/integrity/digest/count/reference checks against synthetic protected cut are required.
4. **Before upgrade mutation**, restore backup into an inactive disposable generation with the prior compatible code, validate original fact families/relationships and safe admissions-closed readability. If restoration/completeness fails, do not start upgrade. Recovery-point verified receipt names cut, source/code identity and performed checks, not just file existence.
5. Stage code/schema conversion in an inactive candidate generation. Each migration transaction changes data, schema advance and success receipt together. Failure before commit leaves none of that transaction; previous committed steps can persist in candidate. Do not claim this is release rollback. Keep protected source and verified recovery point intact.
6. After candidate integrity/compatibility and fence checks, atomically activate code **and data generation** via installation envelope; code loader resolves the same generation, preventing mixed code/schema. Crash during envelope replacement selects either valid old or valid new manifest, never two active writers. Admissions remain closed until actual post-activation checks and operation reconciliation policy hold. A committed defective build can still require release recovery; successful activation is not acceptance.

Acknowledgements during upgrade must be either forbidden new work or durable attributed outcomes of previously admitted operations. The latter are preserved in the spool, with source operation/epoch/event ID and payload; this spool owns **new observations while canonical writer is fenced**, not a second copy of canonical operation decisions. Import each once after healthy activation or recovery, preserving original context. Never drop an acknowledged late observation because it occurred after the cut. Upgrade completion drains/verifies that spool before reopening admissions; unknown operations remain explicitly visible.

## Plugin-independent release/manual recovery

Standalone tool uses stable envelope/manifest and historical exports; it does not load/import the plugin, register tools, run automatic migrations or require its runtime. Offline instructions and compatible manager/code remain reachable outside Loom. Exact commands/runbook are downstream delivery documentation, not invented executable production steps here.

Inspect target identity, recovery cut, active/broken code and schema, all protected payloads, newer acknowledged work and outstanding effects. Fence writers/admissions before changing anything. Preserve the broken generation, recovery spool and newer raw envelopes in read-only quarantine with verified digests; never edit them to manufacture valid state. Wrong identity, corrupt/incomplete point, unsupported required format, disk/permission failure or inability to fence gives refusal with owned remedy. If inspection cannot establish delta, loss is unknown, not zero.

Restore into a **new inactive generation**, with matching prior code. Recover pre-cut acknowledged closure and retain later original history/spool under stable references. Do not blindly merge newer-schema facts into prior execution state. Where safe normalized import is verified it preserves both; otherwise retain attributable recovery history and mark current use unproven. Preview active-current-state losses separately from retained historical bytes. If activation would discard newer acknowledged work from current state, require actual specific user consent naming installation, target cut, delta and consequence. Hash that preview into decision; changed target/delta requires renewed consent. No response, stale consent or inability to disclose material loss refuses destructive activation; offer preservation/owned reconciliation, not an automatic reset. Keeping a quarantined file is not falsely advertised as zero loss of active progress.

Restore receipt records source/cut, user decision where needed, verification and actual activation outcome. Atomic envelope switch occurs only after code/state/fence/closure validation. Interrupted staging leaves originals active/intact and staging inspectable; interrupted activation is resolved by envelope generation identity/checksum, not rerunning mutation. Re-enter read-only first; verify current contracts/proof and then reopen admissions. Original reviews remain original subject judgments, never fresh PASS.

**External effects are not restored.** Combine protected operation inventory, quarantined post-cut facts and recovery spool into an inspection history with deduplicated original identities. Missing outcome is unknown. Release restore uses a new generation/epoch and cannot replay old operation tokens. Before dependent effect execution, establish observed outcome or an authorized adapter strategy proven nonduplicating (for example query exact operation/ref or provider-supported idempotency); without it retain owned wait. Neither state restore nor consent to current-state loss authorizes repeating uncertain effects. Resource consumption is retained/reconciled from post-cut receipts, not reset to obtain free attempts.

## Publication incident regression: actual denial versus advertised authority

Run inside synthetic contained host with native permission hooks and the same control-plane interfaces, using disposable repositories; never reproduce against the staged adapter/user repository. Required trace:

1. Seed foreign staged/dirty contribution in shared destination; record its index/worktree/ref digest. Assign Designer/Specifier/Architect directory-subtree scope; admit native patch in their isolated custody without exact-path workaround. Record base→output receipt under exact attempt/capability. Control-plane preflight and native hook report identical inputs/reasons.
2. Stage exact owned operands and hookless commit with those exact operands, separately exercising optional `--`. Both actual parser and native hook admit; compare published tree/contribution chain. Foreign shared destination bytes/index remain unchanged. Valid publication must not require user manual commit or global index clearing.
3. Reviewer independently reviews exact artifacts; admits permitted status-only bookkeeping. Actual native patch emits the receipt consumed by staging. Scope elevation is neither necessary to reconstruct provenance nor misclassified product repair. Broader semantic edits are denied; status publication cannot grant self-review.
4. Negative contrasts: replace owned bytes after receipt, mix unknown foreign delta, replay old-attempt token, request arbitrary role/path, change ref before commit, and repair then ask same repairer for PASS. Deny exactly the missing predicate while preserving history/unaffected paths.
5. Kill between edit and receipt and between commit and response; recover from retained actual native invocation/bytes/ref evidence or report unproven/unknown. Never create a provenance claim solely because the model says it wrote the file.

Trace contains source/host identity, target/epoch, capability basis, **actual denying or admitting native hook**, parser normalized proposal, mutation receipts, command result, publication/effect observation, consumer tuple and finite next path. An 'authorized' status followed by unchanged-input hook denial is a failing internal contradiction, not a genuine permission wait. Manual human publication is logged as workaround burden and cannot PASS this trace. Current incident manual commit is preserved as original publication evidence, not retroactively attributed to Reviewer authoring admission.

## Independent gates and measurable evidence

**Reliability acceptance:** P1–P7 required representative journeys reach real authorized outcome or genuine boundary; required traces have zero manual state reconstruction, invented receipts, fake terminal transitions and routine continuation prompts. Classify necessary changed-input verification, real user decisions/resource waits and external uncertainty separately.

**Simplification acceptance:** P8 plus source/write-path inventory verifies actual writer removal listed in parent decision; rebuild all projections and show facts/decisions unaffected. Count duplicate maintained decisions removed, surviving writers, coordination calls, unnecessary dispatch/reruns, contradictions, Loom-caused blocks and unresolved outcomes. Fewer prompts/LOC or a merged fix cannot substitute. Working journeys cannot waive removal; removal cannot waive failed journeys.

Evidence packages preserve original attempt/input/source/authority identity, real observations, actual reviewer/acceptance identity and minimized counterexamples. Missing physical proof remains unproven. Two independently recorded acceptance results cannot be inferred from each other or planning completion.
